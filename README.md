# MAKETEO By @EVRICHUNTER

Vocal tracking and production channel strip (VST3, JUCE 8, C++17). All DSP is original and self-contained: no commercial plugins, impulse
responses or convolution are used.

```
MIC IN -> in trim -> AUTOTUNE -> RIDER -> HOLLYWOOD -> U47 -> REVIVAL -> 8-BAND EQ -> DE-ESS HIGH -> DE-ESS LOW
       -> 1176 -> LA-2A -> SSL 4000 J EQ -> MAAG EQ4 -> MAIN VOCAL OUTPUT
                                                         |-> REVERB | DELAY | NEW YORK | BRIGHTNESS | DOUBLER | TUBE  (returns summed back)
OUT = (MAIN + sum of parallel returns) * out trim        -- no limiter, no AGC, no hidden normalisation
```

## Get the Windows VST3
1. Put this folder in a GitHub repository (the workflow is `.github/workflows/build.yml`, same pattern as the Brightness Sause project; I have no access to your
   existing repo, so adapt the path if you keep several plugins in one repo).
2. Actions -> **Build VST3 (Windows x64)** -> Run workflow. The job builds and runs the headless DSP test-suite with MSVC, then builds the VST3.
3. Download artifact `MAKETEO-VST3-Windows-x64` and copy the `.vst3` folder to `C:\Program Files\Common Files\VST3\`; in FL Studio rescan plugins.

Local build: `cmake -B build -A x64 && cmake --build build --config Release --target Maketeo_VST3` (add `-DMK_LTO=OFF` for faster iteration).
DSP tests without JUCE: `cd Tests && g++ -O2 -std=c++17 -I../Source dsp_test.cpp -o dsp_test && ./dsp_test`.

## Latency (measured, not assumed)
Every module is causal with zero lookahead and **zero latency except AUTOTUNE**, which needs a fixed delay for pitch-synchronous grain extraction.
The latency is reported to the host only while AUTOTUNE is active (bypassed = 0 samples) and depends on **Input Type**:

| Input Type | Range | Latency @48 kHz (v1 -> now) |
|---|---|---|
| Soprano | 170 Hz and up | 807 -> **719** samples = 15.0 ms |
| Alto / Tenor | 95 Hz and up | 1431 -> **1282** samples = 26.7 ms |
| Low Male | 65 Hz and up | 2084 -> **1871** samples = 39.0 ms |

Where the delay comes from: a pitch-synchronous grain is two periods long and must be read up to one period (+ the snap window) beyond the moment it is first needed, so
the unavoidable delay is about 2.5 periods of the lowest pitch the Input Type allows. v2 sizes it from that geometry (formerly a 2.8-period rule of thumb) and snaps grains
to the peak of a window one period long that reaches only 0.25 period into the future. Measured over 48 extreme runs the smallest remaining safety margin is 28 samples,
a hard read-guard makes reading not-yet-arrived audio impossible, and the pitch algorithm itself is unchanged (v1 vs v2 A/B: identical pitch error, periodicity and jump
counts on 8 voice ranges plus a glide with vibrato). The YIN detector is 40 % cheaper (four-accumulator loop, same maths). Going lower would require a different
algorithm or a higher lowest-pitch limit, so it was not done.

This is a real limitation for monitoring through the plugin: record with direct monitoring (or with AUTOTUNE bypassed) and enable it when mixing.
The test-suite measures the AUTOTUNE lag by cross-correlation (1431 = reported) and checks every other module's impulse response starts at sample 0.
While bypassed AUTOTUNE keeps recording its input history so switching it on is a smooth ~10 ms cross-fade.

## Behaviour notes
* Parallel returns: MIX is a power-law taper (gain = mix^1.5, 50 % = -9 dB). A chain with MIX 0 % is bit-identical to the main signal. 100 % adds a
  full-level copy, exactly like a console return, so use it deliberately (defaults are 25-35 %).
* The main signal is never changed by a parallel chain. Brightness reuses the very same 8 EQ band settings as the main EQ (it follows them live);
  EQ AMOUNT scales the band gains (high/low-pass filters are unaffected).
* De-essers: split-band dynamic cut (subtractive band-pass, linked stereo gain, attack/release smoothing). LISTEN routes the detected band to the output.
* Saturators use first-order antiderivative anti-aliasing (no oversampling, no added latency); aliasing is reduced, not eliminated.
* PRESETS: 11 factory + user presets saved as XML in `%APPDATA%\Evric Hunter\MAKETEO\Presets`. Undo/Redo covers knob, toggle and LED edits.
* Parameter automation, state save/restore: all 209 parameters are standard JUCE parameters; the project state is the APVTS XML. LISTEN is never restored as "on".

## Validation status (what was and was not verified)
Verified headlessly (`Tests/dsp_test.cpp`, 87 checks, all passing): parameter table and presets; every module audible and bypass bit-transparent; parallel
routing (MIX 0 % identical, main untouched); latency; Autotune accuracy (6 scenarios, within 12-20 cents of target, unvoiced noise untouched); Rider levelling;
both de-essers; compressor behaviour; EQ responses incl. the extended ranges; reverb decay and stability; delay timing and tempo sync; doubler decorrelation; tube
harmonics; identical output for block sizes 32/64/128/256/480; 160 random and extreme sessions at 44.1/48/88.2/96 kHz with no NaN/Inf; no clicks when switching any module;
CPU with every module and every parallel chain active: about 21 % of one core of the build machine at 48 kHz (all block sizes).
The plugin compiles as VST3 and Standalone on Linux and the GUI was rendered and inspected.

**Not verified here (needs you):** the Windows/MSVC build (the workflow does it), loading and automation inside FL Studio, real-time stress over long playback and
recording sessions, listening tests. Preset values are calibrated by measurement and engineering judgement, not by ear on real vocals: expect to fine-tune them.

## Known limitations (documented on purpose)
* AUTOTUNE is monophonic, works best on clean, close-miked voice, and its quality depends on the detector: breathy passages, very fast runs and large corrections
  can sound processed. Corrections are limited to +-3 semitones around the target; a Hard Tune setting is intentionally audible.
* The analog "emulations" (1176, LA-2A, U47, Hollywood, SSL, Maag, tube) are original DSP built from the general behaviour of those units (fixed-threshold FET with fast
  detector, two-cell optical release, tone-shaping plus asymmetric saturation, console-style EQ curves). They are not component-level models and will not null against hardware.
* The interface has three pages: VOCAL (default; simple artist controls: tuning with live note/cents readout, voice character, compression, real level meters),
  FX (on/off + one amount control per effect, EDIT opens the full parameters) and ADVANCED (all 209 original parameters grouped by processor, with short Spanish
  explanations). The five VOICE sliders and the compression slider are *derived controls*: they move several real parameters and read their position back from them,
  so presets and automation always stay in sync; they are not extra host parameters. Window 1200 x 760, resizable down to 1000 x 680 with a reflowing layout.
